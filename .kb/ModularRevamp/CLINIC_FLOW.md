# Clinic Flow — from the marketing page to a working clinic

The whole journey of a **Clinic-only tenant**, in the order it happens. Use it to
design the screens in sequence, then to build them, and to tick both off as you go.
Pharmacy, Lab and HR are out of scope here, but the steps they share with Clinic
are tagged so those modules can skip what is already done. Decisions (Dn) refer to
[SPEC.md](SPEC.md).

## How to read it

**Branch availability (P9 · D30–D32) applies to every screen, not only settings.** Three things to draw wherever they occur:

1. **Setting it** — an "Available at: every branch / chosen branches" control on each shareable master (rows marked D30). A user whose roles cover some branches only sees those branches.
2. **Using it** — every picker and search (products, suppliers, templates, charts, usage templates, reason codes, job titles) shows only what is available at the current branch; an org-wide view shows a branch chip on narrowed items.
3. **Its edge states** — D31: a narrowed item a branch still holds shows "Not available here · using up stock" and blocks ordering/receiving; D32: moving it to a branch where it is not available is blocked with "Make it available at <branch>" for whoever may change that.

**Scope** — who else needs the step:

| Tag      | Meaning                                                                                                                        |
| -------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `Core`   | Every tenant, whatever it bought. **Done once — Pharmacy, Lab and HR reuse it as is.**                                         |
| `Core~`  | Core screen whose _content_ changes per module (e.g. the module cards in onboarding). Reuse the screen; add the module's part. |
| `Shared` | Inventory (D3). Comes with Clinic (off by default, D14), Pharmacy and Lab. **Designed once.**                                  |
| `Clinic` | Clinic module only.                                                                                                            |

**Design** — desktop (1440) frames only: `✅` drawn · `◐` partly drawn, the gap is
named after it · `☐` not drawn. Tablet and phone are not tracked here.
**Build** — `☐` not built in the revamp · `✅` built. Every row starts `☐`; the
**Today** column is the pre-revamp route that already does the job, so the build
usually starts from it.

> Design status checked against the Paper file **rcln**, desktop frames, on
> 2026-10-07. Frame codes are the artboard names in Paper.

## What a Pharmacy-only or Lab-only tenant can skip

Everything tagged `Core` is already designed and built by the time they arrive.
`Core~` screens are reused but need that module's piece added (its module card in
2.3 / 3.5, its default roles in 3.13, its Admin section, its Home tiles, its Reports
section, its invoice source). `Shared` (Part 7) is reused whole; Pharmacy adds the
counter and dispensing on top. Everything tagged `Clinic` is not theirs.
